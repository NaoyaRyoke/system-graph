# Deployment

Prefer TLS termination at a maintained reverse proxy (Caddy/nginx/Traefik or a cloud LB), then a private HTTP backend, then a private Rust JSON child. An embedded TLS server would add certificate reload/trust-store responsibilities to this adapter; it is not the beta recommendation. The Caddyfile is a template with reserved example names and operator-provisioned certificate files; it was not a live public HTTPS deployment. No ACME, trust-store change or public listener is part of the PoC.

Configure canonical HTTPS origin exactly. Have the proxy forward its fixed matching Host and strip forwarded identity/host headers. Keep Origin checking; do not solve proxy integration by disabling it. An operator must validate actual TLS/proxy/credential policy before exposing a service. Full MCP Protected Resource Metadata/authorization-server discovery is not implemented by the JWT integration skeleton.

Build the verification target before runtime. Both Node and Rust base images are pinned to multi-architecture index digests, not mutable tags alone. Linux AMD64 build/tests/demo and signal/read-only container checks are local Docker results. Windows GNU is local; Windows MSVC and native ARM64 are workflow targets, not local execution claims. ARM64 image manifests exist; the dedicated manual native ARM64 job builds/runs verification. Native ARM64 runtime acceptance remains pending.

Each workspace gets a separate container, readonly graph mount and private network. The public executable rejects multiple-workspace config. Backend `0.0.0.0:3000` is container-namespace binding only, and has no host port. A separate fixed-route test gateway publishes 127.0.0.1:18974, without arbitrary URL/path forwarding. `docker-check.mjs` creates two isolated internal networks (no gateway/default route) plus one ingress bridge. Backends need no outbound HTTP/DNS service except Docker-local neighbor name resolution. Pinned JWKS is loaded from config, not fetched during queries. Package downloads happen only during builds.

The fixed test gateway has an outbound route and is not an egress-isolated public edge. It cannot be advertised as public-production hardened. Backends cannot reach external test destinations and cannot mount another graph. Internal networks do not protect against a hostile host or Docker daemon. Use host firewall/VM/orchestrator policy for stronger egress requirements; no host policy was changed here.

Require nonroot UID/GID 10001, read-only root/mounts, cap-drop ALL, no-new-privileges, memory 256MiB for small graphs, bounded PID/CPU and tmpfs, healthcheck and restart policy chosen by the operator. The scale graph needs separately measured higher memory headroom; do not extrapolate the 256MiB small-fixture limit. No restart policy is enabled in the test. Readiness checks the actual graph before listening; health becomes unavailable when the child is failed. The next authorized request may perform a bounded worker restart.

On SIGTERM stop ingress, close pipes, reap workers and exit. Container restart preserves mounted snapshots and requires no graph migration or user registration. Snapshot update: generate/rescan to a new path, integrity/FK check, provision ownership, then restart with explicit compatible config. Never overwrite a live graph. Rollback: stop only this deployment, restore previous image/config/snapshot references. No shared daemon/network/volume settings are changed.

The test cleanup removes exact owned containers/networks, retaining local images, build cache and ignored synthetic artifacts. Provision production DB/config ownership for UID 10001; do not copy synthetic world-readable test permissions to real data. No real credentials are included in the image, Docker metadata or examples.


The blocker follow-up runtime is `FROM scratch`, with actual shared ELF dependencies, Node production packages, fixed JavaScript entrypoints, the engine and license/source data only. Audit does not rely on dpkg existing in the final image. Pin safe DNS search configuration (`--dns-search . --dns-option ndots:0`), retain the startup guard and fixed C locale. Do not introduce LANGUAGE/LOCALDOMAIN/RES_OPTIONS, LD_PRELOAD/LD_LIBRARY_PATH/GCONV_PATH, arbitrary native modules or alternate unguarded entrypoints; those invalidate the contextual OS advisory assessment. No updated container is published while release gates remain open.
